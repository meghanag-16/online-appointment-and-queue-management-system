# Deploying MediQueue on Render

The website and the API run on Render's free plan; the MySQL database is hosted on Aiven (free plan).
`render.yaml` in the repository describes both Render services.

| Piece | Where | Plan |
|-------|-------|------|
| Website (`mediqueue-web`) | Render static site | Free |
| API (`mediqueue-api`) | Render web service, Docker | Free (sleeps after 15 min idle) |
| Database | Aiven for MySQL 8 | Free |

## 1. Create the database (Aiven)

1. Sign up at aiven.io and create a **MySQL** service on the **Free** plan (pick a region close to Render's Singapore, e.g. Mumbai or Singapore).
2. When it is running, open **Overview → Connection information** and note **Host**, **Port**, **User** (`avnadmin`), **Password** and **Database** (`defaultdb`).
3. Your JDBC URL is:
   ```
   jdbc:mysql://HOST:PORT/defaultdb?sslMode=REQUIRED
   ```
   The API creates all tables itself on first start (Flyway).

## 2. Create the services (Render Blueprint)

1. Sign up at render.com with your GitHub account and allow access to this repository.
2. **New → Blueprint**, choose the repository and branch `main`. Render reads `render.yaml` and lists `mediqueue-api` and `mediqueue-web`.
3. Fill in the values it asks for:

| Service | Key | Value |
|---------|-----|-------|
| mediqueue-api | `SPRING_DATASOURCE_URL` | the JDBC URL from step 1 |
| mediqueue-api | `SPRING_DATASOURCE_USERNAME` | `avnadmin` |
| mediqueue-api | `SPRING_DATASOURCE_PASSWORD` | the Aiven password |
| mediqueue-api | `APP_SEED_ADMIN_PASSWORD` | a strong password for `admin` |
| mediqueue-api | `APP_SEED_DEFAULT_PASSWORD` | a strong password for the other demo accounts |
| mediqueue-web | `VITE_API_BASE_URL` | `https://mediqueue-api.onrender.com` (fix in step 3 if Render gives another address) |

4. **Apply**. The first API build takes a few minutes. `APP_JWT_SECRET` is generated by Render.

## 3. Connect the website to the API

1. Open **mediqueue-api** and copy its address (top of the page, e.g. `https://mediqueue-api.onrender.com`).
2. Open `https://<that address>/api/v1/health` — it should show `{"status":"UP","database":"UP"}`.
3. If the address differs from what you entered for `VITE_API_BASE_URL`, open **mediqueue-web → Environment**, correct it, and click **Manual Deploy → Deploy latest commit** (the address is built into the site).
4. Open the website's address and sign in as `admin` with `APP_SEED_ADMIN_PASSWORD`.

`APP_CORS_ALLOWED_ORIGINS` defaults to `https://*.onrender.com`. To allow only your site, set it to the exact website address (or add your own domain).

## 4. Automatic deploys

Both services use `autoDeployTrigger: checksPass`: a push to `main` deploys only after the GitHub Actions checks pass. Each service rebuilds only when its own folder changed.

## 5. Smoke test

1. GitHub → **Settings → Secrets and variables → Actions → Variables**: add
   - `RENDER_API_URL` = the API address
   - `RENDER_SITE_URL` = the website address
2. **Actions → Smoke test (deployed site) → Run workflow** after a deploy. It also runs every morning.

## 6. Protect `main`

GitHub → **Settings → Branches → Add branch protection rule** for `main`:
- Require a pull request before merging, with 1 approval.
- Require status checks to pass: `Backend lint`, `Frontend lint`, `Backend unit + integration tests`, `Frontend unit tests`, `Docker images build`, `End-to-end tests (Cypress, full stack)`.
- Require branches to be up to date before merging.

## Rollback and backups

- **Rollback:** Render → service → **Events** → pick an earlier successful deploy → **Rollback**.
- **Database backups:** Aiven keeps automatic backups of the service. For your own copy:
  ```bash
  mysqldump --ssl-mode=REQUIRED -h HOST -P PORT -u avnadmin -p defaultdb > mediqueue-backup.sql
  ```
- **Schema changes** are new files in `mediqueue-backend/src/main/resources/db/migration` (`V3__...sql`); they run on the next deploy.

## Free plan notes

- The API sleeps after 15 minutes without requests; the first request then takes about a minute.
- Scheduled jobs (nightly slot top-up, appointment reminders) run only while the API is awake; slots are also topped up on every start.
- Lab report files are stored in the database, so nothing is lost when the API restarts.
